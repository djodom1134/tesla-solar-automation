### Response envelope

- **Success:** HTTP 200 `{"response":{"result":true,"reason":""}}`. The proxy emits **no** top-level `error`/`error_description` on success — do not require them.
- **Car-rejected (nominal):** still **HTTP 200** — `{"response":{"result":false,"reason":"<text>"},"error":"","error_description":""}`. No `omitempty`, so `result` is always present and `error` is an empty string, never null. **Parse on `response.result`, never on presence of `error`.**
- **Reason is NOT a stable enum on the signed path.** The proxy builds `"car could not execute command: " + ResultReason.PlainText` (or `…: unspecified error`). Prefix-strip, then treat the remainder as opaque. Unsigned/legacy vehicles get Tesla's short tokens instead — **the same failure yields different strings by transport.**
- **Benign allowlist** (HA `tesla_fleet` + `teslemetry`): treat `result:false` as success when reason ∈ `{already_set, not_charging, requested}`. Homey additionally allows `is_charging`, `complete`.
- **Missing/wrong-typed param** → HTTP 400 with a car-shaped body: `{"response":{"result":false,"reason":"missing percent param"}}` or `"invalid percent param"`. **`getBool` demands JSON `true`/`false`; `getNumber` demands a JSON number** — `{"on":"true"}` / `{"percent":"80"}` are REJECTED.
- **Unknown command** → HTTP 400, literal body `{"response":null,"error":"invalid_command","error_description":""}`.
- **Path form:** the proxy intercepts only `/api/1/vehicles/{VIN}/command/{name}` (7 segments, `segment[5]=="command"`) and demands a **17-character VIN** — a numeric Fleet id returns 404 `expected 17-character VIN in path (do not user Fleet API ID)` *(typo is upstream)*. Tesla's own API accepts either.
- **HTTP statuses:** 400 invalid_command/field/request · 401 mobile_access_disabled / login_required · 403 missing scope **or** "Tesla Vehicle Command Protocol required" · 405 not allowed · 406 Content-Type not JSON · **408 Device Not Available (asleep — wake first)** · 412 precondition / unregistered partner · 421 wrong region (re-resolve base URL) · 422 semantic **or** "Vehicle does not yet support the Tesla Vehicle Command Protocol" · 423 account locked · 429 rate limited (`RateLimit-Reset`/`Retry-After`) · 451 privacy · 499 client closed · 500/503/504 server or vehicle timeout · 540 Device Unexpected.
- **Protocol faults** surface in `error`, not `reason`, as `MessageFault_E` names (`MESSAGEFAULT_ERROR_BUSY`, `_TIMEOUT`, `_UNKNOWN_KEY_ID` → "your public key has not been paired with the vehicle", `_INVALID_SIGNATURE`, …). Retriable: BUSY, TIMEOUT, INVALID_SIGNATURE, INVALID_TOKEN_OR_COUNTER, INTERNAL, INCORRECT_EPOCH, TIME_EXPIRED, TIME_TO_LIVE_TOO_LONG.
- **VCSEC-domain** failures (lock/unlock/trunk/frunk/charge port): `"vcsec could not execute command: "` + `GENERICERROR_{NONE,UNKNOWN,CLOSURES_OPEN,ALREADY_ON,DISABLED_FOR_USER_COMMAND,VEHICLE_NOT_IN_PARK,UNAUTHORIZED,NOT_ALLOWED_OVER_TRANSPORT}`.
- **Signing:** required end-to-end for 2021+ Model 3/Y, refreshed S/X, Cybertruck. `set_vehicle_name`, `set_pin_to_drive`, `reset_pin_to_drive_pin` require it on **every** vehicle. The proxy auto-detects unsupported VINs, caches, and forwards unsigned thereafter.
- **`days_of_week` is a STRING.** Proxy `getDays` accepts case-insensitive `SUN/SUNDAY, MON/MONDAY, TUES/TUESDAY, WED/WEDNESDAY, THURS/THURSDAY, FRI/FRIDAY, SAT/SATURDAY` + `ALL`(127) + `WEEKDAYS`(62) → bitmask Sun=1,Mon=2,Tue=4,Wed=8,Thu=16,Fri=32,Sat=64. **`TUE` and `THU` (3-letter) are NOT accepted.** Sending an int → `invalid days_of_week param`.
- **Schedule ids are epoch seconds** (`uint64`). Omit/`0` → new schedule. Echo the exact id to modify.
- **Non-idempotency.** Safe to blind-retry: `door_lock`, `door_unlock`, `set_charge_limit`, `set_charging_amps`, `set_temps`, absolute `adjust_volume`. **Never blind-retry:** `media_toggle_playback`, `media_volume_up/down`, `add_/remove_charge_schedule`, `add_/remove_precondition_schedule`.
- Proxy serialises per-VIN with a mutex (VCSEC fails out of order), 10s default timeout; concurrent same-VIN requests block and can 503.

## 5. UNIT AND ENUM GOTCHAS

1. **`gui_settings` NEVER changes the payload.** It is a display preference you apply at render time. Every one of these is fixed on the wire regardless of it:
   - `odometer` — **miles**
   - `charge_state.battery_range` / `est_battery_range` / `ideal_battery_range` / `charge_miles_added_rated` / `charge_miles_added_ideal` — **miles**
   - `charge_state.charge_rate` — **miles per hour**
   - `drive_state.speed` — **mph**; `active_route_miles_to_arrival` — **miles**
   - `vehicle_state.tpms_pressure_*` / `tpms_rcp_*_value` — **bar**
   - `vehicle_state.speed_limit_mode.*_mph` — **mph**
   - **all** `climate_state` temperatures — **Celsius**
   
   A single response therefore mixes **metric temps with imperial distances**. Confirmed three ways: TeslaMate unconditionally calls `Convert.miles_to_km/1`; HA declares `UnitOfLength.MILES`/`UnitOfSpeed.MILES_PER_HOUR` natively; Tesla's telemetry doc names the field "Charge Rate Mile Per Hour" → `charge_state.charge_rate`.

2. **`gui_distance_units` is a RATE string** — `"mi/hr"` or `"km/hr"` — even though it governs distance display. **Match on the prefix**, never `== "mi"`.

3. **Doors vs windows use opposite prefix orders.** Doors are DRIVER/PASSENGER-first (`df`=driver **front**, `dr`=driver **rear**, `pf`, `pr`); windows are FRONT/REAR-first (`fd_window`=**front** driver, `rd_window`=**rear** driver). `df` and `fd_window` are *different corners of different axes*. Mixing them is a silent, plausible-looking bug.

4. **Door/window integers: `0` = CLOSED, non-zero = OPEN.** Tesla's protobuf models every one as a plain `bool`, serialised 0/1. Empirically: HA's `vehicle_data_alt.json` has `fd/fp/rd/rp_window`, `ft`, `rt` all `== 1`; `vehicle_data.json` has them all `== 0`. TeslaMate uses `df > 0`. HA `cover.py` is stricter for windows: `OPEN=1` → open, `CLOSED=0` → closed, **anything else → unknown**. Safest UI rule: `!= 0` is open.

5. **`shift_state == null` is the normal parked/asleep value** — the API returns `null` far more often than `"P"` (all four dumps show `null`). Likewise `speed == null` when stationary. Coalesce both. HA maps `null → "p"` via `SHIFT_STATES.get(str(x), "p")`. There is no `L`/`B`/`S`.

6. **Never use voltage or power as an "is charging" proxy.** `charger_voltage` reads **`2`, not `0`,** when idle — in Tesla's own sample, both HA fixtures, and the 2026 dump. Gate on `charging_state in {"Starting","Charging"}` — exactly what HA's charge switch does.

7. **`charger_power` is an INT kW.** A 7.7 kW home charge shows as 7 or 8. For real power compute `charger_voltage × charger_actual_current × (charger_phases or 1)`.

8. **`"<invalid>"` is a sentinel STRING, not an enum member.** Appears for `conn_charge_cable`, `fast_charger_type`, `fast_charger_brand`, `charge_port_color`, and `dashcam_state`. Render as em-dash/"None", never verbatim. HA's cable-connected sensor is literally `lambda x: x != "<invalid>"`. Note `charge_port_color` also has a genuine `"Off"` value — **do not conflate `"Off"` with `"<invalid>"`.**

9. **Timestamp units are mixed inside the same response.** Epoch **milliseconds** (13 digits): `charge_state.timestamp`, `climate_state.timestamp`, `drive_state.timestamp`, `vehicle_state.timestamp`, `gui_settings.timestamp`, `software_update.scheduled_time_ms`. Epoch **seconds** (10 digits): `drive_state.gps_as_of`, `tpms_last_seen_pressure_time_*`, `scheduled_charging_start_time`, `scheduled_departure_time`, schedule `id`s. Multiplying the wrong one by 1000 lands you in the year ~58000.

10. **Three different time encodings for schedules.** Epoch seconds: `scheduled_charging_start_time`, `scheduled_departure_time`. Minutes after midnight (vehicle-local): `scheduled_charging_start_time_app`, `scheduled_charging_start_time_minutes`, `scheduled_departure_time_minutes`, `off_peak_hours_end_time`. Tesla warns its scheduled-charging timestamps "report incorrectly — treating the reported value as Pacific Time will yield the date and time in the vehicle's timezone."

11. **READ/WRITE type mismatch on `climate_keeper_mode`:** reads back as a **string** (`off`/`keep`/`dog`/`camp`/`unknown`), but `set_climate_keeper_mode` takes an **int 0-3**. Same on COP: reads `"Off"`/`"On"`/`"FanOnly"`, writes two booleans `(on, fan_only)`.

12. **`defrost_mode` has two incompatible scales.** REST `climate_state.defrost_mode` is `0=off, 1=normal, 2=max`. The Fleet **Telemetry** `DefrostModeState` enum is `Unknown=0, Off=1, Normal=2, Max=3, AutoDefog=4` — offset by one, with an extra state. Same trap on `ClimateKeeperModeState` (`Unknown=0, Off=1, On=2, Dog=3, Party=4`). **Never cross-map REST against telemetry enums.**

13. **Seat indexing is inconsistent across the three seat commands** — the #1 silent-failure trap. `remote_seat_heater_request.seat_position` is **0-based** (0-8). `remote_seat_cooler_request.seat_position` is **1-based** (1-2). `remote_auto_seat_climate_request.auto_seat_position` is **1-based** (1-2). And `remote_seat_cooler_request.seat_cooler_level` shifts by one through the proxy (working values 1-4, not 0-3).

14. **`is_climate_on` is not user intent.** It goes true for climate keeper, dog/camp mode, cabin overheat protection and preconditioning. A UI showing "Climate: On" from it will light up when the user did nothing. Use `is_auto_conditioning_on`.

15. **Software-update idle sentinels are weird:** `status` is `""` (empty string, not null); `version` is often `" "` (a single space); `install_perc` idles at **1**, not 0. Gate the whole update UI on `status ∈ {available, downloading, downloading_wifi_wait, scheduled, installing}` — never on `install_perc > 0` or untrimmed `version`.

16. **Type inconsistencies to guard:** `santa_mode` is an **int** 0/1, not a bool. `supercharger_payment_needed` is the **string `"false"`**. `speed_limit_mode.*_mph` arrive as ints (69, 120, 50) *or* floats (85.0, 120.0). `id` is 63-bit and loses precision in JavaScript — use `id_s`. `native_location_supported` is 0/1, not a bool. HA's alt fixture sets `minutes_to_full_charge` to the string `"bad value"` — Tesla does emit type-inconsistent garbage here.

17. **Whole-key absence is the dominant failure mode, not null.** Location keys (`latitude`, `longitude`, `native_*`, `heading`, `gps_as_of`, `corrected_*`) are **omitted entirely** without location access — what remains is `power`, `shift_state`, `speed`, `timestamp`, and `active_route_*`. `active_route_*` keys vanish **individually**. Hardware-gated keys (`sentry_mode*`, `homelink_*`, `speed_limit_mode`, `sun_roof_*`, `steering_wheel_*`, rear/third-row seat heaters, `bioweapon_mode`, `seat_fan_*`) are absent, not null. **Use `.get()` everywhere.**

18. **Two gates are required for location, and both are silent.** (1) The token needs the `vehicle_location` scope. (2) On firmware 2023.38+ the request must **also** pass `location_data` in `endpoints`. Correct scope with no `location_data` = no coordinates, no error. Requesting it shows a location-sharing icon on the car's screen.

19. **`endpoints` is mandatory and omission is silent.** Semicolon-separated, URL-encoded (`%3B`), from: `charge_state, climate_state, closures_state, drive_state, gui_settings, location_data, charge_schedule_data, preconditioning_schedule_data, vehicle_config, vehicle_state, vehicle_data_combo`. Omit `gui_settings` and the **whole object is absent** (not empty) — which is exactly why the real 2026 capture has none.

20. **Asleep vehicles return HTTP 408 with no body at all** — you get *no* `charge_state`, not one with null fields. Handle 408 as "asleep", `POST /wake_up`, then poll `state`. Tesla: "Regularly polling this endpoint is not recommended and will be expensive." Frequent wake-ups defeat sleep and drain the 12V.

21. **Two separate amps concepts, easy to wire wrong.** `charge_current_request` / `charge_current_request_max` are the request+ceiling pair HA binds its slider to (min 0, step 1, fallback max 32). `charge_amps` mirrors the request but no production client reads it. `charger_actual_current` is the **live measured** draw. `charger_pilot_current` is the EVSE's advertised ceiling. Write via `set_charging_amps` with body key **`charging_amps`**.

22. **`scheduled_charging` and `scheduled_departure` write the SAME tri-state** `scheduled_charging_mode` (Off/StartAt/DepartBy). Disabling one while the other is active turns the whole feature off. Read `charge_state` first and restore the prior mode. Both endpoints are deprecated from fw 2024.26+ in favour of `add_charge_schedule` / `add_precondition_schedule`, whose data lives in the separate `charge_schedule_data` / `preconditioning_schedule_data` endpoints — **not** in `charge_state`.

23. **`time_to_full_charge` (float hours) and `minutes_to_full_charge` (int minutes) are the same quantity** — Tesla's telemetry doc maps its single "Time To Full Charge" field to both keys. Prefer minutes for precision; both read 0 when idle. Semantics: if the session is part of a trip, it is time until ready to continue; otherwise time until the user-set limit.

24. **`display_name` does not exist in `vehicle_data`.** Verified absent across Tesla's docs sample, both HA fixtures, and the 2026 capture. Use `vehicle_state.vehicle_name`. It *is* returned by `GET /api/1/vehicles` and `/api/1/products`. Binding a UI to `response.display_name` renders "—" forever.
